# weather_station — 실제 기상관측소 기록

다른 케이스는 변화를 하나 심어 만든 데이터지만, 이 케이스는 **실제로 측정한 기록**입니다.
가정용 기상관측소가 1분마다 남긴 실외 기록을 10분 간격으로 줄였고, 기간은 2026-04-23부터
08-31까지(16,243행)입니다. 정답을 심지 않았기 때문에 ddoc이 실제 데이터에서 무엇을 맞히고 무엇을
놓치는지가 그대로 드러납니다.

```bash
python make.py                 # 장마 (기본) → data/ref.csv, data/cur.csv
python make.py yearly-reset    # 연간 강우 누적값이 초기화된 날
ddoc diff data/ref.csv data/cur.csv --lang ko --report note.html
```

데이터는 패키지에 들어 있어(`ddoc/examples/data/weather_station.csv.gz`) 따로 내려받지 않습니다.
`ddoc serve` 첫 화면의 예제 사례 중 두 개와 `ddoc examples generate timeseries` 도 같은 기록을 씁니다.

## 데이터

| 열 | 뜻 | 10분으로 줄인 방법 |
|---|---|---|
| `time` | 10분 구간의 시작 시각 | — |
| `temp_c`, `humidity`, `dew_point_c`, `feels_like_c` | 기온(℃), 습도(%), 이슬점(℃), 체감온도(℃) | 평균 |
| `wind_ms`, `gust_ms`, `wind_dir_deg` | 풍속, 돌풍(m/s), 풍향(°) | 평균, 최댓값, 원형 평균 |
| `pressure_inhg` | 기압 (관측소 설정대로 inHg) | 평균 |
| `solar_lux`, `uvi` | 일사(lux), 자외선 지수 | 평균 |
| `rain_hourly_mm` | 지난 1시간 강우 (이동 합계) | 마지막 값 |
| `rain_event_mm` … `rain_yearly_mm` | 이번 비·오늘·이번 주·이번 달·올해 누적 강우 | 마지막 값 |

- 실내 온습도는 집 안 상태가 드러나므로 뺐습니다.
- 1분 기록이 5개 미만인 구간은 버렸습니다. 그래서 8월에 로거가 멈췄던 시간(하루 이상 빈 날이
  여러 번)은 값을 지어내지 않고 빈 시간으로 남아 있습니다.
- 원본에서 이 파일을 만드는 과정은 [prepare.py](prepare.py)에 있습니다(원본은 저장소에 없음).
- 데이터는 저장소와 같은 Apache-2.0 라이선스를 따릅니다.

## 이야기와 결과

| story | 기준 → 현재 | 판정 (점수) | 가장 변한 열 | 판독 |
|---|---|---|---|---|
| `monsoon` | 6/21–7/4 → 7/5–7/18 | **DRIFT** (0.178) | 이슬점 0.909 · 습도 0.276 | 수준 이동형 · 이동·확산형 |
| `yearly-reset` | 5/18–5/31 → 6/1–6/14 | **OK** (0.037) | 이슬점 0.097 | 잠복 변화형 · 산포 변화형 |
| `season` | 5/1–5/14 → 7/24–8/6 | **DRIFT** (0.303) | 이슬점 1.000 · 체감 0.865 · 기온 0.831 | 수준 이동형 · 산포 변화형 · 고착형 |
| `next-days` | 7/24–27 → 7/28–31 | **DRIFT** (0.072) | 기압 0.365 · 주간 강우 0.311 | 국소 이동형 · 산포 변화형 · 고착형 · 이동·확산형 |

**장마 (`monsoon`).** 7월 5일 무렵부터 습하고 비 오는 날이 이어졌습니다. 이슬점 평균이 18.3℃에서
23.8℃로, 습도가 65%에서 81%로 올라섰습니다. 고장이 아니라 계절이 바뀐 것입니다. 판정은 DRIFT이고,
할 일은 기준 데이터를 새 계절로 바꾸는 것입니다.

**연간 누적값 초기화 (`yearly-reset`).** 6월 1일 0시에 관측소의 연간 강우 누적값이 1,293.6mm에서 0으로
돌아갔습니다. 날씨가 아니라 기기 설정이 만든 변화입니다. 누적값을 다른 열처럼 수준으로 비교하면
`rain_yearly_mm`과 `rain_monthly_mm`의 점수가 1.0이 되어 DRIFT가 납니다. ddoc은 시간 순으로
늘어나기만 하고 초기화 때만 줄어드는 열을 찾아 비교에서 빼고, 그 이유를 진단서의 검사 대상과
콘솔에 적습니다. 남은 날씨 열로 보면 OK입니다.

```
✅ OK — 심각도: 없음 · 점수 0.0366 (기준 0.15)
   ⤷ 비교 제외 — 시간이 갈수록 늘어나기만 하는 누적 열: rain_event_mm,
rain_daily_mm, rain_weekly_mm, rain_monthly_mm, rain_yearly_mm
```

지난 1시간 강우(`rain_hourly_mm`)는 이동 합계라 오르내리므로 비교에 남습니다. 시간대 순환 열
(`hour` 같은 0–23)도 매번 같은 값에서 다시 시작하므로 누적값으로 보지 않습니다.

## 실제 데이터에서 알아 둘 점

**날씨는 며칠 단위로 움직입니다 (`next-days`).** 같은 계절의 나흘과 그다음 나흘도 DRIFT입니다.
평균 기압은 같지만 기압계가 지나가며 폭이 두 배가 되었고(표준편차 0.030 → 0.063 inHg), 주간 강우는
기준 기간 중간에 주가 바뀌며 65.3mm에서 0으로 돌아간 뒤 현재 기간 내내 0입니다. 앞의 것은 실제
변화이고, 뒤의 것은 나흘 동안 값이 두 가지뿐이라 누적값으로 알아볼 수 없었습니다. 기준 기간은 비교할
기간보다 충분히 길게 잡으세요.

**비가 오지 않은 주는 "고착형"으로 읽힙니다.** 현재 기간에 비가 한 번도 오지 않으면 강우 열이 전부
0이라 값이 하나로 고정된 모양입니다. 0이 기준 기간에도 가장 흔한 값이었다면 판독 문구가 그렇게
알려 줍니다(`rain_event_mm: 현재 데이터의 100.0% 가 0 — 기준에서도 가장 흔한 값 (91.7%)`). 센서가
멈춘 것이 아니라 조용한 기간일 수 있다는 뜻입니다.

## 판독이 놓친 것

장마에서 가장 크게 변한 이슬점은 평균이 2.9σ 올라가면서 폭은 0.57배로 좁아졌습니다(표준편차
1.87 → 1.07). 습한 공기가 포화에 가까워질 때 생기는 모양입니다. 지금의 유형 목록에서 수준
이동형은 폭이 비슷해야 하고, 이동·확산형은 폭이 넓어져야 해서, **이동하면서 좁아지는 열은 어느
유형에도 들지 않습니다.** 판정(DRIFT)과 점수는 맞지만, 판독 문구에는 이슬점이 나오지 않습니다.
`season` 의 이슬점(표준편차 4.06 → 0.81)과 기온도 같은 이유로 판독에서 빠집니다.
