ddoc 3.0.0 기준(2026-11-25). "확인"은 테스트나 실제 실행으로 본 것이고, 확인하지 못한 것은 그렇게
적었습니다. 판정에 BLIND 가 있듯이, 이 페이지도 모르는 것은 모른다고 씁니다.

## 플러그인

| 플러그인 | 상태 | 확인 |
|---|---|---|
| categorical | 됨 | 테스트, 데모 |
| tabular | 됨 (EDA 보고서 렌더) | 테스트 |
| evidently | 됨 | 테스트 |
| timeseries | 됨 | 테스트 (torch 없는 전체 플러그인 환경에서 332개 통과) |
| audio | 됨 | 같은 환경에서 테스트 |
| vision | 됨 | torch + CLIP ViT-B/16 으로 e2e 테스트와 임베딩 지도 실제 실행. CLIP 은 플러그인에 들어 있어(MIT) GitHub 없이 설치됩니다 |
| text | 됨 (점수 척도는 아래 한계 참고) | torch + CLIP 으로 e2e 테스트와 `diff --with-embeddings` 실제 실행(네트워크 없이). 내려받을 말뭉치 없음 — 단어는 정규식, 영어 불용어는 scikit-learn 목록 |

`ddoc doctor` 는 설치는 됐지만 불러지지 않는 플러그인을 빠진 모듈과 함께 보여줍니다.

## 알려진 한계

- **판정 민감도.** 변화를 하나만 심은 드릴 가운데 9개(평균 1σ 이동, 산포 2배, 극단값 8%, 새 범주
  20%, 구성비 30%p 이동 등)가 판정은 OK 입니다. 유형 판독은 변화를 정확히 짚고 "잠복 변화형"으로도
  알리지만, 분포 점수(Jensen–Shannon 발산)가 단일 속성 기준 0.25 에 닿지 않습니다.
- **작은 표본의 오경보.** 반대로 쪽마다 30행쯤이면 변하지 않은 데이터도 대부분 DRIFT 로 판정되고, 유형
  판독도 잡음에 반응합니다(같은 분포의 10열 표 97%). 100행부터는 오경보가 없습니다. 이 둘은 점수가 변화의
  크기와 표본 잡음을 구분하지 않아서 생기며, 후보 방식의 비교와 제안은 [판정 민감도](sensitivity.md)에
  있습니다. 기본값은 아직 바꾸지 않았습니다.
- **날짜·시간 열은 이름이나 값의 모양으로 찾습니다.** 연도 네 자리가 없는 형식(`7/1`, `2026년 7월 1일`,
  유닉스 시각 숫자 등)은 찾지 못해, 기간이 다른 두 데이터에서 늘 드리프트로 나올 수 있습니다.
  `ddoc probe` 로 미리 확인하세요.
- **이동하면서 폭이 좁아진 열은 판독 유형에 없습니다.** 실측 기상 기록의 장마에서 가장 크게 변한 이슬점(평균
  2.9σ 상승, 표준편차 ×0.57)이 어느 유형에도 들지 않아 판독 문구에서 빠집니다. 판정과 점수는 맞습니다
  ([weather_station](../zoo/weather_station/#판독이-놓친-것)).
- **누적값 열은 시간 열이 있을 때만, 값이 충분히 움직일 때만 알아봅니다.** 짧은 기간에 값이 두세 가지뿐인
  누적 열(나흘 동안의 주간 강우)은 알아보지 못해 비교에 남습니다.
- **임베딩 지도는 항목이 적으면 불안정합니다** (한쪽 20개 미만이면 표시). 같은 이미지만 있으면 중심
  이동을 계산하지 않습니다.
- **플러그인마다 점수 척도가 다릅니다.** 판정 기준(0.15 / 0.25)은 0–1 점수를 전제로 하지만, vision 은 PSI,
  text 는 기준 평균으로 나눈 Wasserstein 거리라 1을 넘습니다(예제 문장 길이 변화에서 `length_chars` 25.8).
  timeseries 는 열의 원래 단위로 평균·분산 차이를 더해, 실측 기상 예제에서 일사량(lux)의 분산 차이 때문에 940만이
  됩니다. 큰 변화는 그대로 DRIFT 이지만 점수 숫자를 플러그인끼리 비교할 수는 없습니다. [판정 민감도](sensitivity.md)의
  결정과 함께 정할 일입니다.
- **분포 비교만 합니다.** 라벨(정답)과의 관계가 바뀐 것(개념 드리프트)이나 모델 성능 영향은 라벨이 있는
  현재 데이터로 따로 재야 합니다.
- **주기성은 두 시점 비교로 구분하지 못합니다.** 요일·계절처럼 반복되는 차이는 비교 구간을 같은
  주기로 맞춰야 합니다([rhythm_not_drift](../zoo/rhythm_not_drift/) 참고).
