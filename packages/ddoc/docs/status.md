# 지금 상태 — 무엇이 되고, 일부만 되고, 남았나

ddoc 3.0.0 기준(2026-11-20). "확인"은 테스트나 실제 실행으로 본 것이고, 확인하지 못한 것은 그렇게
적었습니다. 판정에 BLIND 가 있듯이, 이 페이지도 모르는 것은 모른다고 씁니다.

## 판정과 진단서

| 항목 | 상태 | 확인 |
|---|---|---|
| `ddoc diff` CSV 판정 (내장 비교기, 플러그인 없이) | 됨 | 테스트, [판독 드릴](../zoo/README.md#판독-드릴) 19개 |
| 유형 판독 17가지 | 됨 | 16가지는 드릴로 정답 확인. 임베딩 분리형은 vision 플러그인 + CLIP 실제 실행으로 확인 |
| 진단서 HTML (주간·야간, 인쇄, 툴팁, 데이터 도면) | 됨 | 헤드리스 Chrome 으로 화면 확인 |
| 진단서 PDF (`.pdf`) · Markdown (`.md`) | 됨 | weasyprint 로 PDF 생성 후 페이지 확인, Markdown 테스트 |
| 데이터 프로필 보고서 (`analyze eda`, CSV) | 됨 | 테스트, 화면 확인 |
| `ddoc doctor` · `ddoc probe` | 됨 | 테스트, 플러그인이 불러지지 않는 환경에서 실제 확인 |
| 상황별 시나리오 (`ddoc scenarios`, `./run.sh menu`, GUI 탭) | 됨 | 테스트 (카탈로그의 명령·옵션이 실제 CLI 에 있는지 포함) |

## 플러그인

| 플러그인 | 상태 | 확인 |
|---|---|---|
| categorical | 됨 | 테스트, 데모 |
| tabular | 됨 (EDA 보고서 렌더) | 테스트 |
| evidently | 됨 | 테스트 |
| timeseries | 됨 | 테스트 (torch 없는 전체 플러그인 환경에서 332개 통과) |
| audio | 됨 | 같은 환경에서 테스트 |
| vision | 됨, **설치에 주의** | torch + CLIP ViT-B/16 으로 e2e 테스트와 임베딩 지도 실제 실행. 다만 코드가 `import clip`(GitHub 의 CLIP 패키지)을 쓰고 의존성도 그것을 요구해, GitHub 에 닿지 않는 환경에서는 설치되지 않습니다. 플러그인 안에 CLIP 이 들어 있으니 그것을 쓰도록 바꾸는 것이 남은 일입니다 |
| text | **확인하지 못함** | 임베딩 지도 연결 코드는 있지만, CLIP 과 nltk 데이터(GitHub 에서 내려받음)가 필요해 이 환경에서는 실행하지 않았습니다 |

`ddoc doctor` 는 설치는 됐지만 불러지지 않는 플러그인을 빠진 모듈과 함께 보여줍니다.

## 알려진 한계

- **판정 민감도.** 변화를 하나만 심은 드릴 가운데 9개(평균 1σ 이동, 산포 2배, 극단값 8%, 새 범주
  20%, 구성비 30%p 이동 등)가 판정은 OK 입니다. 유형 판독은 변화를 정확히 짚고 "잠복 변화형"으로도
  알리지만, 분포 점수(Jensen–Shannon 발산)가 단일 속성 기준 0.25 에 닿지 않습니다. 기준값과 점수
  방식(발산 대신 거리 등)은 드릴 표를 근거로 정할 일로 남아 있습니다.
- **날짜·시간 열은 이름으로 찾습니다** (`date`, `time`, `_at` 등). 이름이 다르면 범주형으로 비교되어
  기간이 다른 두 데이터에서 늘 드리프트로 나올 수 있습니다. `ddoc probe` 로 미리 확인하세요.
- **임베딩 지도는 항목이 적으면 불안정합니다** (한쪽 20개 미만이면 표시). 같은 이미지만 있으면 중심
  이동을 계산하지 않습니다.
- **분포 비교만 합니다.** 라벨(정답)과의 관계가 바뀐 것(개념 드리프트)이나 모델 성능 영향은 라벨이 있는
  현재 데이터로 따로 재야 합니다.
- **주기성은 두 시점 비교로 구분하지 못합니다.** 요일·계절처럼 반복되는 차이는 비교 구간을 같은
  주기로 맞춰야 합니다([rhythm_not_drift](../zoo/rhythm_not_drift/) 참고).
