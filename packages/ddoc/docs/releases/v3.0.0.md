# ddoc v3.0.0 릴리스 노트

## 릴리스 일자
Unreleased

## 개요

ddoc v3.0.0 은 ddoc 를 **두 데이터를 비교해 판정하고 근거를 남기는 도구** 로
좁힌 메이저 릴리스입니다. 데이터 버전 관리, 모델 학습, 실험 추적처럼 git /
DVC / 학습 도구가 이미 하는 일은 ddoc 에서 제거했습니다. 명령, hookspec,
extras, REST 요청 필드가 제거되었으므로 하위 호환이 깨집니다.

hookspec 버전: `1.0.0` → `2.0.0`

## ✨ 추가 (v2.1.0 노트 이후)

- `ddoc diff <ref> <cur>` — 한 줄 판정 `OK` / `DRIFT` / `BLIND`, exit code
  가 곧 판정 (0 / 1 / 2). 생 CSV 는 플러그인 없이 내장 비교기로 판정.
  `--report` 로 검사 보고서 형식의 HTML 진단서 생성 — 발행처(`--issuer`)·문서
  번호·발행 일시, 검사 대상(기준/현재의 규모·기간·열 구성과 열 대조, 원하면
  `--sample-rows` 로 앞 N행), 요약 대시보드와 판독 한 줄, 유형 판독(17가지 드리프트 유형을
  측정값에 대어 본 카드 — 신호, 뜻, 흔한 원인, 먼저 할 일, 주의), 데이터 도면(열마다 부품 하나, 썸네일·판정·번호
  붙은 설명과 상세로 가는 링크), 판정 근거, 계통별 검사표(측정값·
  기준·적합/주의/부적합), 속성별 점수 그래프, 속성별 상세 그래프(범주형 기준→현재
  비교, 수치형 분포 겹침과 중앙값, 값이 몇 개뿐인 정수 열은 값별 막대), 원본
  데이터 특징, 패턴(새 값 등장, 값 소멸, 구성비 변화, 범위 이탈, 평균 이동,
  산포·결측률 변화)에 맞춘 점검 항목, 한계. 단일 파일로 오프라인에서 열리고,
  화면 테마(자동·주간·야간) 전환과 인쇄 / PDF 버튼(인쇄는 항상 흰 바탕), 그래프마다
  표 보기와 값 표시를 제공. 같은 진단이 `--json` 출력의 `diagnosis` 필드에 코드와
  수치로 실림
- CSV 비교기는 날짜·시간 텍스트 열을 기간 표시에만 쓰고 비교하지 않음 (기간이
  다르면 타임스탬프는 늘 달라 항상 드리프트로 나오던 문제)
- Drift Zoo — 고전 드리프트 패턴 재현 케이스와 회귀 테스트
- GitHub Action (`action.yml`) — CI 데이터 게이트
- `ddoc serve` — REST API 와 브라우저 GUI
- `ddoc recipe` — fetch → analyze → report → export 를 YAML 로
- `ddoc report render` — drift 입력(`ddoc diff --json` 또는 drift envelope)은 같은
  진단서로, Markdown 은 판정·판독·검사표·점검 체크박스로(PR 코멘트용), PDF 는 같은
  HTML 로. `--issuer`, `--threshold`, `--attr-threshold`
- 임베딩 지도 — `ddoc diff --with-embeddings` 로 이미지·텍스트 임베딩을 함께 비교하면
  진단서에 PCA 산점도와 중심 이동·이웃 섞임이 들어가고, 갈라졌으면 "임베딩 분리형"으로 판독.
  vision·text 플러그인이 `embedding_projection` 을 결과에 실음
- vision·text 플러그인이 OpenAI CLIP(MIT)을 패키지 안에 담아, `git+https://github.com/openai/CLIP`
  없이 설치됩니다. 어휘 파일이 wheel 에 들어가도록 package-data 를 명시
- 판독 드릴(`zoo/drills.py`, `zoo/eval.py`, `./run.sh zoo`) — 유형마다 변화 하나만 심은 케이스와
  정답. 속성 유형은 빠짐·추가·열까지 엄격히, 데이터 전체 유형과 판정은 그것을 겨냥한 드릴에서
  확인. 결과표가 zoo README 에 생성되며 "판정 민감도"(판독은 맞는데 판정이 OK 인 케이스)를 함께 보여줌
- `ddoc examples generate vision` 이 같은 단색 5장 대신 도형·색이 다양한 40장을 만들고, shifted 는
  어둡고 푸른 톤 — 임베딩 지도를 의미 있게 보여줌
- 상황별 시나리오 카탈로그(`ddoc/scenarios.conf`) — `ddoc scenarios`(목록, `--md` 치트시트, `run <id>
  --set 이름=값 [-n]`, `menu`), `./run.sh menu`, `ddoc serve` 의 "상황별" 탭(명령 복사, 탭에서 열기),
  [치트시트](../cheatsheet.md) 가 모두 같은 파일을 읽음. 카탈로그의 명령·옵션이 실제 CLI 에 있는지
  테스트로 확인
- `ddoc diff --report` 가 확장자로 형식 결정(`.html` · `.md` · `.pdf`), `ddoc analyze eda --report`
- `ddoc doctor` — Python, 코어 라이브러리, 플러그인이 실제로 불러지는지, 선택 기능(PDF·serve·
  임베딩)을 점검. `ddoc probe <ref> [<cur>]` — diff 전에 데이터 종류, 판정 주체, BLIND 여부와
  이유, CSV 면 비교할 열·한쪽에만 있는 열을 미리 보여줌
- `ddoc analyze eda` 의 내장 CSV 프로파일러와 데이터 프로필 보고서 — 규모·기간·열별 분포,
  품질 소견(결측, 상수, 식별자형, 극단값, 표기 변형, 텍스트 숫자, 중복 행), 진단서와 같은 형식
- `ddoc serve` 의 `POST /diff` 와 GUI 첫 탭 "진단 (diff)" — 판정 카드와 진단서를 함께 표시
- `ddoc export drift-report`, `ddoc fetch`,
  `ddoc examples`, `ddoc transform`, `ddoc plugin detectors`
- 플러그인: categorical, tabular, evidently
- 한글 리포트: `--lang ko` 또는 `DDOC_LANG=ko` 로 진단서, `report render`
  리포트, 안내 문구, 터미널 출력을 한국어로 출력. 기본은 영어이며
  `--json` 의 키와 판정 값은 언어와 관계없이 영어로 유지

## 🗑️ 제거

| 제거 항목 | 대안 |
|---|---|
| `ddoc init`, `ddoc add`, `ddoc snapshot` 와 workspace / snapshot 계층 | 데이터 버전 관리는 git / DVC 로. 분석은 경로를 직접 지정 |
| `ddoc analyze drift <baseline> <current>` 스냅샷 인자 | `--data-path-ref` / `--data-path-cur` |
| `ddoc analyze eda [snapshot]`, `--save-snapshot`, `--strict-hash` | `ddoc analyze eda --data-path <p>` |
| `ddoc exp train / eval / best`, `ddoc train`, recipe 의 `train` 단계 | 학습은 기존 학습 도구에서 수행 |
| `ddoc ingest` | 데이터 입력은 `ddoc fetch`, 결과 전달은 `ddoc export` |
| `ddoc vis` (Streamlit GUI) | `ddoc serve` 의 GUI |
| v1 legacy 명령 (`dataset`, `lineage`, `commit`, `checkout`, `log`, `status`, `alias`, `exp run/list/show/compare/status`) | v2 이후 대응 명령 |
| hookspec `data_add`, `exp_run`, `exp_show`, `retrain_run`, `vis_run` | — |
| extras `[exp]`, `[yolo]`, `[exp-yolo]`, `[exp-vision]`, `[vis]`, `[nlp]`, `[ingest]` | — |
| 플러그인 yolo, vis, nlp, reference-engine, keti-temporal | nlp 는 text 플러그인 사용 |
| REST `/analyze/drift` 의 `baseline` / `current`, `/analyze/eda` 의 `snapshot` / `save_snapshot` / `strict_hash` 필드 | 경로 필드 사용 |
| 의존성 `networkx`, `requests`, `fpdf` | — |

경로 인자가 빠지면 `analyze drift` / `analyze eda` 는 `path_mode_incomplete`
오류 코드와 exit code 2 로 끝납니다.

## 🐛 수정

- 플러그인 하나가 입력을 처리하지 못해 예외를 내도 다른 플러그인의 결과가
  사라지지 않습니다 (`diff`, `analyze drift`, `analyze eda`). 모든 플러그인이
  실패할 때만 `plugin_error` 로 끝나며, 실패한 플러그인과 오류를 함께
  보여줍니다.
- `ddoc examples generate` 가 일반 설치 (`pip install ./ddoc`, Docker, GitHub
  Action) 에서도 동작합니다. 예제 생성기가 이제 패키지 안
  (`ddoc.examples.factories`) 에 있습니다.
- tabular 플러그인이 표 데이터의 드리프트 결과를 EDA 양식으로 그려 드리프트
  점수가 빠지던 문제.
- evidently 플러그인: pandas 3 에서 import 가 실패하던 문제 — `pandas<3` 으로
  제한.
- `ddoc serve` 가 JSON 이 아닌 요청 본문에 422 대신 500 을 내던 문제.
- text 플러그인이 최근 nltk(3.8.2 이후)에서 `punkt_tab` 말뭉치가 없어 실패하던 문제. 이제 nltk 를 쓰지 않아
  내려받을 것이 없습니다(단어는 정규식, 영어 불용어는 scikit-learn 목록). 단어 수에 들어가는 토큰이 nltk 와
  조금 달라(`don't` 를 한 단어로 셈) 이전 버전의 text 속성 점수와는 조금 다를 수 있습니다.
- `ddoc diff` 가 실행한 디렉터리에 플러그인의 `analysis/diff/metrics.json` 을 남기던 문제.
- PDF 진단서·보고서를 쓸 때 PDF 엔진의 로그가 stdout 에 섞여 `--json` 출력이 깨지던 문제. 로그는
  stderr 로 갑니다.

## 🔒 보안

- `ddoc serve` 를 API 키 없이 띄우면 이 컴퓨터만 상대합니다. 브라우저에서 연 다른 웹페이지가
  로컬 서버를 부르지 못하도록, `Host` 가 localhost · 127.0.0.1 · ::1 · 바인딩 주소 ·
  `DDOC_ALLOWED_HOSTS` 가 아닌 요청(DNS rebinding)과 `Origin` 이 다른 변경 요청은 403 입니다.
  키를 설정하면 이 검사는 꺼지고 키가 보호합니다. `--host 0.0.0.0` 에 키 없이 띄워 다른 컴퓨터에서
  IP 로 접속하던 구성은 키를 설정하거나 `DDOC_ALLOWED_HOSTS` 에 이름을 더해야 합니다.
- API 키·레시피 쓰기 토큰·관리 토큰을 상수 시간으로 비교합니다.
- REST 요청과 레시피의 경로 값이 `-` 로 시작하면 명령행 옵션으로 읽히지 않도록 거절합니다.

## 🔄 변경

- 저장소 구조: 코어는 `packages/ddoc/`, 플러그인은 `packages/plugins/` 로
  옮겼습니다. 저장소 루트에서 `pip install -e packages/ddoc` 로 설치합니다.
- `packages/ddoc/Dockerfile` 은 저장소 루트에서 빌드합니다
  (`docker build -f packages/ddoc/Dockerfile .`), 포트 8765, non-root 실행.
- `ddoc.__version__` 은 설치된 패키지 메타데이터에서 읽습니다.

## 마이그레이션

- 스냅샷 ID 로 분석하던 스크립트는 해당 스냅샷의 데이터 경로를 직접 넘기도록
  바꿉니다. 데이터 버전은 git / DVC 로 체크아웃한 뒤 경로를 지정하면 됩니다.
- `retrain_run` 등 제거된 hookspec 을 구현한 외부 플러그인도 그대로
  로드되지만, 해당 구현은 더 이상 호출되지 않습니다. 정리를 권장합니다.
- 예제: 저장소 루트의 `examples/` (Docker 배포, CI 게이트, 애플리케이션 연동).
