# ddoc v3.0.0 릴리스 노트

## 릴리스 일자
Unreleased

## 개요

ddoc v3.0.0 은 ddoc 를 **두 데이터를 비교해 판정하고 근거를 남기는 도구** 로
좁힌 메이저 릴리스입니다. 데이터 버전 관리, 모델 학습, 실험 추적처럼 git /
DVC / 학습 도구가 이미 하는 일은 ddoc 에서 제거했습니다. 명령, hookspec,
extras, REST 요청 필드가 제거되었으므로 하위 호환이 깨집니다.

hookspec 버전: `1.0.0` → `2.0.0`

## ✨ 추가 (v2.1.0 노트 이후)

- `ddoc diff <ref> <cur>` — 한 줄 판정 `OK` / `DRIFT` / `BLIND`, exit code
  가 곧 판정 (0 / 1 / 2). 생 CSV 는 플러그인 없이 내장 비교기로 판정.
  `--report` 로 검사 보고서 형식의 HTML 진단서 생성 — 발행처(`--issuer`)·문서
  번호·발행 일시, 검사 대상(기준/현재의 규모·기간·열 구성과 열 대조, 원하면
  `--sample-rows` 로 앞 N행), 요약 대시보드와 판독 한 줄, 유형 판독(18가지 드리프트 유형을
  측정값에 대어 본 카드 — 신호, 뜻, 흔한 원인, 먼저 할 일, 주의), 데이터 도면(열마다 부품 하나, 썸네일·판정·번호
  붙은 설명과 상세로 가는 링크), 판정 근거, 계통별 검사표(측정값·
  기준·적합/주의/부적합), 속성별 점수 그래프, 속성별 상세 그래프(범주형 기준→현재
  비교, 수치형 분포 겹침과 중앙값, 값이 몇 개뿐인 정수 열은 값별 막대), 원본
  데이터 특징, 패턴(새 값 등장, 값 소멸, 구성비 변화, 범위 이탈, 평균 이동,
  산포·결측률 변화)에 맞춘 점검 항목, 한계. 단일 파일로 오프라인에서 열리고,
  화면 테마(자동·주간·야간) 전환과 인쇄 / PDF 버튼(인쇄는 항상 흰 바탕), 그래프마다
  표 보기와 값 표시를 제공. 같은 진단이 `--json` 출력의 `diagnosis` 필드에 코드와
  수치로 실림
- CSV 비교기는 날짜·시간 텍스트 열을 기간 표시에만 쓰고 비교하지 않음 (기간이
  다르면 타임스탬프는 늘 달라 항상 드리프트로 나오던 문제)
- Drift Zoo — 고전 드리프트 패턴 재현 케이스와 회귀 테스트
- GitHub Action (`action.yml`) — CI 데이터 게이트
- `ddoc serve` — REST API 와 브라우저 GUI
- `ddoc recipe` — fetch → analyze → report → export 를 YAML 로
- `ddoc report render` — drift 입력(`ddoc diff --json` 또는 drift envelope)은 같은
  진단서로, Markdown 은 판정·판독·검사표·점검 체크박스로(PR 코멘트용), PDF 는 같은
  HTML 로. `--issuer`, `--threshold`, `--attr-threshold`
- 임베딩 지도 — `ddoc diff --with-embeddings` 로 이미지·텍스트 임베딩을 함께 비교하면
  진단서에 PCA 산점도와 중심 이동·이웃 섞임이 들어가고, 갈라졌으면 "임베딩 분리형"으로 판독.
  vision·text 플러그인이 `embedding_projection` 을 결과에 실음
- vision·text 플러그인이 OpenAI CLIP(MIT)을 패키지 안에 담아, `git+https://github.com/openai/CLIP`
  없이 설치됩니다. 어휘 파일이 wheel 에 들어가도록 package-data 를 명시
- 판독 드릴(`zoo/drills.py`, `zoo/eval.py`, `./run.sh zoo`) — 유형마다 변화 하나만 심은 케이스와
  정답. 속성 유형은 빠짐·추가·열까지 엄격히, 데이터 전체 유형과 판정은 그것을 겨냥한 드릴에서
  확인. 결과표가 zoo README 에 생성되며 "판정 민감도"(판독은 맞는데 판정이 OK 인 케이스)를 함께 보여줌
- `ddoc examples generate vision` 이 같은 단색 5장 대신 도형·색이 다양한 40장을 만들고, shifted 는
  어둡고 푸른 톤 — 임베딩 지도를 의미 있게 보여줌
- 상황별 시나리오 카탈로그(`ddoc/scenarios.conf`) — `ddoc scenarios`(목록, `--md` 치트시트, `run <id>
  --set 이름=값 [-n]`, `menu`), `./run.sh menu`, `ddoc serve` 의 "상황별" 탭(명령 복사, 탭에서 열기),
  [치트시트](../cheatsheet.md) 가 모두 같은 파일을 읽음. 카탈로그의 명령·옵션이 실제 CLI 에 있는지
  테스트로 확인
- `ddoc diff --report` 가 확장자로 형식 결정(`.html` · `.md` · `.pdf`), `ddoc analyze eda --report`
- `ddoc doctor` — Python, 코어 라이브러리, 플러그인이 실제로 불러지는지, 선택 기능(PDF·serve·
  임베딩)을 점검. `ddoc probe <ref> [<cur>]` — diff 전에 데이터 종류, 판정 주체, BLIND 여부와
  이유, CSV 면 비교할 열·한쪽에만 있는 열을 미리 보여줌
- `ddoc analyze eda` 의 내장 CSV 프로파일러와 데이터 프로필 보고서 — 규모·기간·열별 분포,
  품질 소견(결측, 상수, 식별자형, 극단값, 표기 변형, 텍스트 숫자, 중복 행), 진단서와 같은 형식
- `ddoc serve` 의 `POST /diff` 와 GUI 첫 탭 "진단 (diff)" — 판정 카드와 진단서를 함께 표시
- `ddoc serve` 의 진단 화면(첫 화면): 기준·현재 칸에 파일·폴더를 끌어다 놓거나 서버 폴더를 탐색해 넣고, 넣는 즉시
  그 데이터의 종류·행·열·기간·열 이름과 판정 전 확인(`probe`)을 보여줍니다. 결과는 판정, 유형 판독 카드와 먼저 할 일,
  열별 점수와 기준·현재 분포 그림, 진단서 전체(HTML·PDF·Markdown 저장, CLI 명령 복사)로 이어집니다. 정답이 있는
  예제 사례 6개(`ddoc.examples.cases`, 둘은 실제 기상관측소 기록)를 한 번에 진단할 수 있고, `/?case=<id>` · `/?ref=…&cur=…&run=1` 주소로 바로
  엽니다. CLI 옵션과 1:1 인 기존 폼은 "고급 도구"로 옮겼습니다. 새 endpoint: `/fs/list`, `/fs/image`,
  `/workspace/uploads`, `/cases`, `/describe`, `/probe`; `POST /diff` 응답의 `view`, `POST /report/render` 의
  `lang` · `issuer`. 탐색은 `DDOC_DATA_ROOT` 안으로 제한되고 올린 파일은 `DDOC_WORKSPACE` 에 하루 동안 둡니다
- 누적·순번 열 비교 제외: 시간 열이 있을 때 시간 순으로 늘어나기만 하고 초기화될 때만 줄어드는 숫자 열(일·월·연
  누적 강우, 누적 횟수, 순번)을 찾아 날짜 열처럼 비교에서 빼고, 콘솔·진단서·`probe`·진단 화면에 이름을 적습니다
  (`--json` 의 `profile.columns.running`). 이동 합계와 시간대 같은 순환 열은 비교에 남습니다
- 실측 예제 데이터: 가정용 기상관측소의 10분 간격 실외 기록 16,243행(`ddoc.examples.weather`). Drift Zoo 의
  [weather_station](../../zoo/weather_station/) 케이스, 진단 화면의 예제 사례 2개(장마 · 연간 누적값 초기화),
  `ddoc examples generate timeseries` 가 이 기록을 씁니다
- 고착형 판독: 현재 값이 기준에서도 가장 흔한 값에 고정되었으면 그렇게 적고(비가 오지 않은 주), 원인에 "조용한
  기간"을 더했습니다
- 투어 `ddoc examples tour <이름>`: 명령 하나가 실제 데이터로 파이프라인 전체를 실행하며 단계마다 이유·실행하는
  명령·그 명령의 출력을 보여 줍니다(`--pause` 는 단계마다 Enter 를 기다림). 첫 투어 `weather` 는 기상 기록으로
  받기 → `probe` → `analyze eda` → `diff --report` → DRIFT 일 때만 Markdown 진단서 → 누적값 초기화 사례(OK)까지
  7단계입니다. 투어는 레시피 한 장이라 `--save` 로 꺼내 `--var` 로 경로만 바꾸면 내 데이터의 파이프라인이 됩니다.
  `./run.sh demo` 가 이 투어를 실행합니다(CI 도). [투어로 배우기](../tutorial/tours.md)
- 레시피: `diff`·`probe` 단계 — DRIFT(1)·BLIND(2) 종료 코드는 판정이지 실패가 아니므로 레시피가 이어집니다.
  `${steps.<id>.verdict}`(OK·DRIFT·BLIND)·`${steps.<id>.returncode}` 로 `when` 조건을 걸 수 있고, 단계에
  `title`·`note`(언어별)를 달 수 있습니다. `ddoc recipe run --narrate` 는 단계마다 제목·설명·명령과 그 명령의 출력을
  보여 주고, `--var name=value` 는 변수를 덮어씁니다. `analyze.eda` 단계가 `report`·`lang` 을 받습니다. 값이 빈
  `with` 키는 옵션을 넘기지 않습니다
- `ddoc examples generate weather [--scenario monsoon|yearly-reset|season|next-days]`: 실측 기상 기록의 두 기간을
  모든 열 그대로 `ref.csv`·`cur.csv` 로
- 실측 이미지 예제: 2채널 블랙박스로 찍은 12분 주행의 프레임 242장(`ddoc.examples.dashcam`, 2MB). 프레임은
  대시보드 위만 남겨(화면의 날짜·시각·속도 제외) 320 × 140 으로 줄였고 이름은 주행 시작부터의 초이며, GPS·센서
  기록은 풀지 않았습니다. 이야기 여섯 개 — 다른 카메라(전방 → 후방), 다음 구간, 같은 구간(잡음 수준), 실제
  프레임에 심은 렌즈 흐림·화질 저하·노출 — 를 `ddoc examples generate dashcam --scenario <이야기>`, Drift Zoo
  [dashcam](../../zoo/dashcam/), 투어 `ddoc examples tour dashcam`(vision 플러그인 필요), 진단 화면의 예제 사례
  3개(이미지 사례는 임베딩 지도를 켜고 진단)로 씁니다. 예제 사례는 이제 이미지 폴더도 될 수 있고, 필요한 플러그인과
  사례만의 diff 옵션을 함께 가집니다(`GET /cases` 의 `needs`·`options`)
- 생성 텍스트·오디오 예제: 메모 앱 고객 문의(`ddoc.examples.support`, 영어 — text 플러그인의 지표와 임베딩이 영어
  기준)와 모터 소리(`ddoc.examples.machine`, 1초 16 kHz WAV 를 표준 라이브러리로). 이야기마다 한 가지만 바꿉니다:
  앱 업데이트(로그인·동기화 불만, 긴 글) · 채팅 말투 · 평범한 두 주, 베어링 마모 · 마이크 이득 · 두 교대.
  `ddoc examples generate support|machine --scenario <이야기>`, Drift Zoo [support_tickets](../../zoo/support_tickets/) ·
  [machine_sound](../../zoo/machine_sound/), 투어 `ddoc examples tour support|machine`, 진단 화면 예제 사례 3개
- 이미지·텍스트·오디오의 속성 판독: 플러그인이 결과에 항목마다 잰 값(`attribute_values`: 속성별 기준·현재 목록)을
  넣으면 `ddoc diff` 가 CSV 의 수치 열과 같은 코드로 요약과 분포를 만들어, 속성마다 유형 판독(수준 이동형,
  이동·수축형 등), 패턴별 점검 항목, 진단서의 기준·현재 분포 그래프가 나옵니다. vision·text·audio 플러그인이
  값을 넘기며, 판정 점수는 각 플러그인의 것 그대로입니다
- 이동·수축형 판독: 평균이 0.5σ 이상 옮겨가면서 산포가 1/1.25 이하로 좁아진 열. 이동·확산형과 같은 문턱을 반대
  방향으로 적용합니다. 전에는 수준 이동형(산포가 비슷)에도 이동·확산형(산포가 커짐)에도 들지 않아, 장마의 이슬점
  (2.9σ 상승, 표준편차 ×0.57)처럼 가장 크게 변한 열이 판독에서 빠졌습니다. 정답이 있는 드릴 `shift-and-narrow` 추가
- `ddoc export drift-report`, `ddoc fetch`,
  `ddoc examples`, `ddoc transform`, `ddoc plugin detectors`
- 플러그인: categorical, tabular, evidently
- 한글 리포트: `--lang ko` 또는 `DDOC_LANG=ko` 로 진단서, `report render`
  리포트, 안내 문구, 터미널 출력을 한국어로 출력. 기본은 영어이며
  `--json` 의 키와 판정 값은 언어와 관계없이 영어로 유지

## 🗑️ 제거

| 제거 항목 | 대안 |
|---|---|
| `ddoc init`, `ddoc add`, `ddoc snapshot` 와 workspace / snapshot 계층 | 데이터 버전 관리는 git / DVC 로. 분석은 경로를 직접 지정 |
| `ddoc analyze drift <baseline> <current>` 스냅샷 인자 | `--data-path-ref` / `--data-path-cur` |
| `ddoc analyze eda [snapshot]`, `--save-snapshot`, `--strict-hash` | `ddoc analyze eda --data-path <p>` |
| `ddoc exp train / eval / best`, `ddoc train`, recipe 의 `train` 단계 | 학습은 기존 학습 도구에서 수행 |
| `ddoc ingest` | 데이터 입력은 `ddoc fetch`, 결과 전달은 `ddoc export` |
| `ddoc vis` (Streamlit GUI) | `ddoc serve` 의 GUI |
| v1 legacy 명령 (`dataset`, `lineage`, `commit`, `checkout`, `log`, `status`, `alias`, `exp run/list/show/compare/status`) | v2 이후 대응 명령 |
| hookspec `data_add`, `exp_run`, `exp_show`, `retrain_run`, `vis_run` | — |
| extras `[exp]`, `[yolo]`, `[exp-yolo]`, `[exp-vision]`, `[vis]`, `[nlp]`, `[ingest]` | — |
| 플러그인 yolo, vis, nlp, reference-engine, keti-temporal | nlp 는 text 플러그인 사용 |
| REST `/analyze/drift` 의 `baseline` / `current`, `/analyze/eda` 의 `snapshot` / `save_snapshot` / `strict_hash` 필드 | 경로 필드 사용 |
| 의존성 `networkx`, `requests`, `fpdf` | — |

경로 인자가 빠지면 `analyze drift` / `analyze eda` 는 `path_mode_incomplete`
오류 코드와 exit code 2 로 끝납니다.

## 🐛 수정

- vision 플러그인이 설치되어 있으면 `ddoc analyze eda` 가 CSV 에 대해 이미지 0장을 분석한 결과를 내고, 그 빈
  결과로 프로필 보고서를 쓰던 문제. 아무것도 분석하지 않은 플러그인 결과는 버리고 내장 CSV 프로파일러가 맡습니다.
- 플러그인으로 비교하면 실행한 폴더에 `.ddoc/cache`(코어 캐시)와 `analysis/`(`analyze eda`), 비교한 이미지
  폴더 안에 `cache/`(vision 플러그인)가 남던 문제. 캐시는 찾기만 할 때는 아무것도 만들지 않고 실제로 저장할 때만
  폴더를 만들며, 데이터 해시가 없는 경로 비교(`ddoc diff`)에서는 저장하지 않습니다. `analyze eda` 는 플러그인
  결과를 쓰지 않았으면 그 실행이 만든 `analysis/` 를 지웁니다.
- 레시피의 `required_plugins` 가 빠졌을 때 설치 안내가 PyPI 이름(`pip install ddoc-vision`)이라 실패하던 문제.
  저장소 폴더나 git 주소로 안내합니다.
- 플러그인 하나가 입력을 처리하지 못해 예외를 내도 다른 플러그인의 결과가
  사라지지 않습니다 (`diff`, `analyze drift`, `analyze eda`). 모든 플러그인이
  실패할 때만 `plugin_error` 로 끝나며, 실패한 플러그인과 오류를 함께
  보여줍니다.
- `ddoc examples generate` 가 일반 설치 (`pip install ./ddoc`, Docker, GitHub
  Action) 에서도 동작합니다. 예제 생성기가 이제 패키지 안
  (`ddoc.examples.factories`) 에 있습니다.
- tabular 플러그인이 표 데이터의 드리프트 결과를 EDA 양식으로 그려 드리프트
  점수가 빠지던 문제.
- evidently 플러그인: pandas 3 에서 import 가 실패하던 문제 — `pandas<3` 으로
  제한.
- `ddoc serve` 가 JSON 이 아닌 요청 본문에 422 대신 500 을 내던 문제.
- text 플러그인이 최근 nltk(3.8.2 이후)에서 `punkt_tab` 말뭉치가 없어 실패하던 문제. 이제 nltk 를 쓰지 않아
  내려받을 것이 없습니다(단어는 정규식, 영어 불용어는 scikit-learn 목록). 단어 수에 들어가는 토큰이 nltk 와
  조금 달라(`don't` 를 한 단어로 셈) 이전 버전의 text 속성 점수와는 조금 다를 수 있습니다.
- `ddoc diff` 가 실행한 디렉터리에 플러그인의 `analysis/diff/metrics.json` 을 남기던 문제.
- PDF 진단서·보고서를 쓸 때 PDF 엔진의 로그가 stdout 에 섞여 `--json` 출력이 깨지던 문제. 로그는
  stderr 로 갑니다.
- 기준을 넘은 속성이 8개를 넘으면 진단서가 만들어지지 않던 문제(검사표의 "외 N개" 행에 기준값이 없었음). 진단서를
  쓰지 못하면 이제 콘솔에 이유를 알리고 `--json` 의 `report_error` 에 남깁니다(판정과 종료 코드는 그대로).
- timeseries 플러그인이 값이 하나뿐인 열(비가 없던 기간의 강우)에서 왜도·첨도를 NaN 으로 남겨 점수 전체가 NaN 이
  되던 문제.

## 🔒 보안

- `ddoc serve` 를 API 키 없이 띄우면 이 컴퓨터만 상대합니다. 브라우저에서 연 다른 웹페이지가
  로컬 서버를 부르지 못하도록, `Host` 가 localhost · 127.0.0.1 · ::1 · 바인딩 주소 ·
  `DDOC_ALLOWED_HOSTS` 가 아닌 요청(DNS rebinding)과 `Origin` 이 다른 변경 요청은 403 입니다.
  키를 설정하면 이 검사는 꺼지고 키가 보호합니다. `--host 0.0.0.0` 에 키 없이 띄워 다른 컴퓨터에서
  IP 로 접속하던 구성은 키를 설정하거나 `DDOC_ALLOWED_HOSTS` 에 이름을 더해야 합니다.
- API 키·레시피 쓰기 토큰·관리 토큰을 상수 시간으로 비교합니다.
- REST 요청과 레시피의 경로 값이 `-` 로 시작하면 명령행 옵션으로 읽히지 않도록 거절합니다.

## 🔄 변경

- **판정 점수.** 속성마다 기준·현재 분포의 Jensen–Shannon **거리**(발산의 제곱근, 0–1)를 내고, 같은 구간의 G-검정
  (2×k, 유의수준 0.001)에서 표본 잡음으로 설명되는 차이는 0 으로 둡니다([ddoc.scoring](../../ddoc/scoring.py)). 기준값은
  0.15 / 0.25 그대로이고, 판정 규칙이 하나 더해졌습니다. 속성 유형이 "해당"이고 같은 잡음 검정을 통과하면(결측 증가는
  결측 개수로 검정) 그것만으로 DRIFT 이고, 판정 근거에 "속성 'x'에서 ○○형이 표본 잡음 범위를 넘어 확인됩니다"가
  나옵니다. 잡음 범위 안의 "해당"은 "가까움"으로 낮추고, 판정이 OK 이면 잠복 변화형으로 알립니다. 결과 JSON 의
  요약에 검정의 p 가 `noise_p`·`missing_p` 로 남습니다. 근거와 측정은 [판정 민감도](../sensitivity.md)에 있습니다:
  드릴·이야기 21/21(이전 11/21), 같은 분포에서 뽑은 30행 10열 표의 오경보 97% → 1.5%, 1,000행에서 평균 0.6σ 이동·
  새 범주 2%·결측 10%p 증가를 잡습니다.
- **모든 데이터에 같은 척도.** 항목마다 잰 값을 넘기는 플러그인(vision·text·audio·timeseries)의 속성, categorical
  레이아웃의 개수 분포, 임베딩 지도(`embedding_separation` = 1 − 이웃 섞임, 이웃 구성의 같은 잡음 검정)를 CSV 열과
  같은 방식으로 매겨 판정합니다. 플러그인이 낸 원래 점수는 `plugin_scores` 에 남고, 저수준 `ddoc analyze drift` 는
  플러그인 점수를 그대로 보여 줍니다. 이미지·텍스트·오디오의 대조군(바뀐 것이 없는 쌍)이 모두 OK(0점)가 되고,
  오디오의 마이크 이득 변경처럼 이전 점수로는 대조군과 구별되지 않던 변화가 갈립니다.
- 바뀌는 것: 점수 숫자가 커지고(발산 0.06 → 거리 0.25) 이전 보고서의 점수나 `--attr-threshold` 를 직접 지정한 CI
  설정과 비교할 수 없습니다. 쪽마다 몇 행뿐인 아주 작은 표본은 OK 가 되고 표본 부족형·잠복 변화형이 사정을 알립니다.
- **시간 순서 기록은 하루 단위로 잡음 검정.** 10분 간격 기록처럼 이웃 행이 닮은 데이터는 행 수만큼의 정보가 없어,
  행을 하나씩 세면 같은 날씨의 두 기간도 71–95% 를 DRIFT 로 판정합니다. 시간 열(timeseries 플러그인은
  `timestamp_column`)이 있으면 행을 달력 날짜로 묶고(한쪽이 3일 미만이면 그쪽을 같은 길이의 6구간으로), 두 기간의
  차이가 블록끼리의 차이보다 큰지를 봅니다. G 통계량의 2차 Rao–Scott 보정과 블록 자유도의 F 검정이고, 행 단위
  검정보다 관대해지지 않습니다. 오경보는 하루끼리 독립에 가까우면 0, 하루가 전날을 많이 닮으면(상관 0.7) 14%.
  결과 JSON 에 `profile.noise_blocks`(묶은 방식)와 열마다 `design_effect`(대략 몇 행이 한 행 몫인지)가 남습니다.
  실측 기상 기록에서 연간 초기화와 나흘 대 나흘은 OK, 장마(0.244)와 계절(0.331)은 DRIFT 입니다.
- **0점의 이유.** 0점은 분포가 같아서일 수도, 차이가 잡음 범위 안이어서일 수도 있습니다. 진단서의 속성별 결과·
  속성별 상세와 진단 화면의 열별 결과가 0점마다 "잡음 범위 안 (거리 0.312, p 0.25, 하루 단위로 셈)", "분포 같음",
  "값 분포는 같음, 결측 0.0% → 25.0%" 중 하나를 적고, 잡음 범위 안의 열은 잡음을 넘었다면 받았을 거리를 점선
  막대로 그립니다. 0점끼리는 거리가 큰 순서입니다. OK 판정의 근거에 "N개 속성이 달라 보이지만 표본 잡음 범위
  안입니다 (가장 큰 것: …)"가 더해지고, 시간 순서 기록이면 검사 대상에 묶은 방식(기준 14일, 현재 14일)이 나옵니다.
  콘솔은 잡음을 넘었다면 기준에 닿았을 열을 "잡음 범위 안" 줄로 보여 줍니다. Markdown 진단서에 판정 근거 절이
  생겼습니다. 결과 JSON 에는 속성별 상태가 `diagnosis.noise`(`state`·`distance`·`p`)로, 잡음 검정 전의 거리가 요약의
  `distance` 로 남습니다.
- 드릴의 "변하지 않은 열"은 같은 분포에서 따로 뽑은 표본입니다. 작은 표본의 무변화 드릴과 잡음 범위 안의 변화
  드릴을 더했습니다(22개).
- `ddoc diff` 의 "가장 변한 속성" 줄은 0점 속성을 보여 주지 않습니다.

- `ddoc analyze eda` 의 화면 출력은 결과 JSON 전체(수백 줄) 대신 내장 CSV 프로필의 요약입니다: 행·열 수와 열 종류,
  기간, 품질 소견. 전체는 `--json` 과 `--report` 에 있습니다. `ddoc examples generate` 의 다음 단계 안내는
  `ddoc diff` 입니다.

- 저장소 구조: 코어는 `packages/ddoc/`, 플러그인은 `packages/plugins/` 로
  옮겼습니다. 저장소 루트에서 `pip install -e packages/ddoc` 로 설치합니다.
- `packages/ddoc/Dockerfile` 은 저장소 루트에서 빌드합니다
  (`docker build -f packages/ddoc/Dockerfile .`), 포트 8765, non-root 실행.
- `ddoc.__version__` 은 설치된 패키지 메타데이터에서 읽습니다.
